# Глоссарий faultline

Один термин на одно понятие. Термины действуют в плане, требованиях, дизайн-документах и коде. Имена в коде — в `моноширинном`.

| Термин | Код | Определение | Не путать с |
|---|---|---|---|
| Спан | `span.Span` | Один OTLP-спан после валидации (`span.New`), неизменяемый | — |
| Пакет | `batch.Batch` (`batch.New`) | Спаны одного OTLP-запроса после валидации плюс момент приёма `ReceivedAt`. Единица записи в журнал | Go-пакет (в тексте пишем «Go-пакет»), OTLP-запрос (сырой, до валидации) |
| Сервис | `resource.ServiceRef` | Пара `{namespace, name}` из атрибутов ресурса: `k8s.namespace.name` (иначе `service.namespace`) и `service.name`. Уровень графа шага 1 | workload (уровень FR-TOP-001, шаг 10: Deployment/StatefulSet), pod |
| Половинка | `role.Role` + `ids.CallKey` | Client-спан (сторона caller) или server-спан (сторона callee) одного вызова, ожидающий пару. «Caller/callee» — стороны вызова; «client/server» — вид спана (`kind.Kind`), в тексте не смешиваются | — |
| Вызов без ответа | `call.Unanswered` → `graph.Node.UnansweredCalls` | Caller-половинка, не нашедшая пару за TTL: вызываемый не ответил, не инструментирован или его server-спан опоздал больше чем на TTL (по одному спану неразличимо). Учитывается на узле вызывающего, ребра не даёт | вызов |
| Ключ вызова | `ids.CallKey` | `{trace_id, id}`: для client — свой `span_id`, для server — `parent_span_id` | `span_id` |
| Вызов | `call.Call` (из двух `call.Party`) | Сопоставленная пара половинок: caller, callee, признак ошибки (ошибка любой из сторон по коду ответа). Вход графа | Exchange (ниже) |
| Exchange | — (шаг 8+) | Запрос/ответ, наблюдённый агентом eBPF без спанов. После разрешения адресов превращается в тот же `Call` | Call |
| Event | — (шаг 2+) | Обобщённое входное событие (спан, лог, точка метрики, exchange) в движке окон | — |
| Буфер ожидания | `matcher.Matcher` (внутри `Builder`) | Половинки, ждущие пару не дольше TTL | журнал |
| Tombstone | `tombstone.Set` (внутри `matcher.Matcher`) | Ключ недавно сопоставленного вызова (`BothSides`) или истёкшей caller-половинки (`CallerOnly`); повтор половинки в течение `tombstoneTTL` (60 s, своё окно, не TTL буфера) считается дубликатом. Дедупликация best effort | — |
| Builder | `topology.Builder` | Доменный фасад: владеет матчером и графом и порядком «истечь → сопоставить → применить», строит снимок | Pipeline (application: журнал ↔ Builder ↔ публикация) |
| Журнал | порты `spanJournal` / `spanFeed` | Упорядоченная очередь пакетов между приёмом и обработкой, ограниченная по байтам (`Batch.Footprint()`). В шаге 1 — `memjournal` в памяти, с шага 3 — NATS JetStream | буфер ожидания |
| Доставка | `processing.Delivery` | Пакет из журнала плюс `Release` — освобождение кредита памяти журнала после публикации снимка с этим пакетом. Не подтверждение durability (оно — по позиции журнала, шаг 5) | — |
| Граф | `graph.Graph` (внутри `Builder`, вход — `graph.Change`) | Агрегат: узлы, рёбра, счётчики, ревизия | снимок |
| Снимок | `topology.Snapshot` | Состояние графа на ревизию; то, что видят читатели. Срезы узлов и рёбер — своя копия у каждого снимка | — |
| Ревизия | `Snapshot.Revision` | Номер изменения графа; растёт только если итерация обработки изменила граф: новый узел или ребро либо любой счётчик узла или ребра. До шага 5 сбрасывается при рестарте | — |
| Узел | `graph.Node` | Сервис на уровне графа; id `svc:` + `url.PathEscape(namespace)` + `/` + `url.PathEscape(name)` — стабилен между ревизиями | индекс узла в ответе API (действителен в одном ответе) |
| Ребро | `graph.Edge` | Направленная пара узлов «caller → callee» со счётчиками вызовов | вызов |
| Приём | `application/ingest` | Сценарий `AcceptBatch`: валидный пакет → журнал | обработка |
| Обработка | `application/processing` | `Pipeline`: журнал → `Builder` → публикация снимка → `Release` | — |
| Событийное время | `eventtime.Interval.End` | Момент окончания спана по часам источника. Окно выбирается по нему | время приёма, время обработки |
| Время приёма | `Batch.ReceivedAt` | Момент записи пакета в журнал по монотонным часам журнала; ставит журнал под своей блокировкой; не убывает вдоль журнала | событийное время |
| Пульс | `batch.Heartbeat` | Запись журнала без спанов: «кандидат watermark не рос `idle_advance_after`». Двигает watermark в простое; пишется только после первой записи с данными | пакет |
| Интервал спана | `eventtime.Interval` | VO: событийное время и латентность спана, каждое может быть неизвестно | окно |
| Окно | `stream.Window`; proto `WindowStats.start` + `Graph.window_size` | `[start, start + size)` событийного времени, `start` кратен `size` от Unix-эпохи | итерация Pipeline |
| Субъект | `handle.Node`, `handle.Edge`; proto `Node`, `Edge` | Узел или ребро графа, у которого считается RED | — |
| Серия | ключ движка `stream.Windows[K, C]` | Окна одного ключа: субъекта, операции субъекта или переполнения субъекта | субъект |
| Ячейка | `red.Cell` / `red.Counts` | Агрегат окна одной серии: запросы, ошибки и (у субъекта) скетч латентности | — |
| Watermark | `stream.Watermark`; proto `Graph.watermark` | `max(prev, кандидат пакета − watermark_delay)`; функция журнала; не убывает | событийное время |
| Кандидат пакета | `batch.Batch.Candidate()` | `min(ReceivedAt, max t спанов пакета с известным временем)`; у пакета без таких спанов кандидата нет; у пульса — `ReceivedAt` | — |
| Опоздание | — | `watermark − t` в момент раскладки события | задержка доставки |
| Вид панели | `stream.PaneKind` → `red.PaneKind`; proto `PaneKind` | `EARLY` — предварительный результат; `ON_TIME` — финальный при проходе watermark через конец окна; `LATE` — обновлённый финальный | — |
| Панель | `stream.Pane` | Метаданные выдачи: окно, вид, ревизия | сводка |
| Сводка окна | `red.WindowStats`; proto `WindowStats` | VO результата окна: запросы, ошибки, p50/p95/p99, покрытие | панель |
| Ревизия окна | `stream.Pane.Revision`; proto `WindowStats.revision` | `ON_TIME` = 1, каждый `LATE` +1; `EARLY` — 0 | ревизия снимка |
| Горизонт | `stream.Config.Slots()` | Число окон серии, живущих одновременно | — |
| Выход на пенсию | `stream.Sink.Retire` | Окно с `end + allowed_lateness ≤ watermark` больше не принимает событий | вытеснение половинки |
| Закрытие серии | `stream.Sink.Closed` | Серия без живых окон удаляется из движка | — |
| Операция | `operation.Operation` | Нормализованный шаблон вызова (`GET /users/{id}`, `oteldemo.CartService/GetCart`) и протокол | span name |
| Владелец | `handle.Node` в `cardinality` | Сервис, под лимитом которого считаются операции: вызываемый (у серии узла — сам узел) | субъект |
| Операции владельца | `cardinality.Registry` | Различные допущенные операции владельца; их ≤ `max_operations_per_service` | серии операций |
| Владелец сверх лимита | `OwnersOverLimit` (в коде везде одно имя); в `pipeline.stats` — `cardinality.services_over_limit` | Владелец, которому отказано в новой операции, пока число его операций не упадёт ниже лимита | — |
| Переполнение | движок переполнения в `traffic`, имя `operation.OverflowName` | Серия `(субъект, __overflow__)` для событий операций сверх лимитов FR-STR-007 | вытеснение |
| Ключ серии | `traffic.SeriesKey` | Семантический id серии для FR-STR-004: вид серии, стороны, протокол и имя операции | хэндл |
| Бюджет скетчей | `sketch.Arena` | Общий предел записей бинов всех скетчей; при исчерпании скетч сливает нижние записи | кредит журнала |
| Живая сводка | `topology.Snapshot` → proto `Node.live`, `Edge.live` | Сводка самого нового окна субъекта, пока оно не закрыто (`EARLY`); обновляется не реже раза в секунду, если окно изменилось. В DOT — строка с `~` | финальная сводка |
| Финальная сводка | `topology.Snapshot` → proto `Node.final`, `Edge.final` | Сводка последнего закрытого окна субъекта (`ON_TIME`, затем `LATE`); детерминирована по журналу, совпадает с пакетным пересчётом | живая сводка |
| Self-alert | `selfalert.Evaluator`, события `windows.*` | Предупреждение faultline о собственном учёте (доля переназначенных или отброшенных опоздавших событий, отставание watermark, лимиты кардинальности, бюджет скетчей): одна запись лога при подъёме (`state=raised`) и одна при снятии (`state=cleared`), с гистерезисом; текущее состояние — группа `alerts` в `pipeline.stats` | алерт Prometheus (шаг 6) |
